# Бекенд авторизації (email + пароль)

Простий сервер на Express для реєстрації та входу користувачів.
Дані зберігаються локально у файлі `database.sqlite` (створюється автоматично).

## Структура

```
backend/
├── server.js           # головний файл, запускає сервер
├── db.js                # підключення до SQLite, створення таблиці users
├── middleware/
│   └── auth.js           # перевірка JWT-токена
├── routes/
│   └── auth.js            # /register, /login, /me
├── frontend-example/
│   └── LoginForm.jsx        # приклад форми логіну на React
├── .env.example
└── package.json
```

## Як запустити

```bash
cd backend
npm install
cp .env.example .env
node server.js
```

Сервер запуститься на `http://localhost:3001`.

## Маршрути (API)

### POST /api/auth/register
Реєстрація нового користувача.

**Тіло запиту:**
```json
{
  "email": "user@example.com",
  "password": "123456",
  "name": "Ім'я (не обов'язково)"
}
```

**Відповідь (201):**
```json
{
  "message": "Реєстрація успішна",
  "token": "eyJ...",
  "user": { "id": 1, "email": "user@example.com", "name": "Ім'я" }
}
```

### POST /api/auth/login
Вхід існуючого користувача.

**Тіло запиту:**
```json
{
  "email": "user@example.com",
  "password": "123456"
}
```

**Відповідь (200):** така сама структура, як і в register — токен + дані користувача.

### GET /api/auth/me
Отримати дані поточного залогіненого користувача. Потребує токен.

**Заголовок:**
```
Authorization: Bearer <token>
```

**Відповідь (200):**
```json
{ "user": { "id": 1, "email": "user@example.com", "name": "Ім'я", "created_at": "..." } }
```

## Як це працює (коротко)

1. **Реєстрація** — пароль ніколи не зберігається як є, він хешується через `bcrypt` (навіть маючи доступ до бази, ніхто не побачить справжній пароль).
2. **Логін** — сервер бере пароль, який ввів користувач, хешує його і порівнює з хешем у базі. Якщо співпадає — видає **JWT-токен**.
3. **Токен** — це підписаний рядок, який підтверджує "я користувач з id=1" протягом 7 днів. Фронтенд зберігає його (наприклад, в `localStorage`) і надсилає в заголовку `Authorization` для доступу до захищених маршрутів (як `/api/auth/me`).

## Підключення з React (форма логіну)

Дивіться `frontend-example/LoginForm.jsx` — готовий приклад форми, яка:
- відправляє email/пароль на `/api/auth/login`
- при успіху зберігає токен в `localStorage`
- показує помилку, якщо пароль невірний

Скопіюйте цей файл у ваш React-проєкт (`src/component/LoginForm.jsx`) і підключіть в `App.jsx` так само, як інші компоненти.

## Важливо перед деплоєм / показом у портфоліо

- Змініть `JWT_SECRET` в `.env` на довгий випадковий рядок (не лишайте `dev-secret-change-me`)
- Файл `.env` не повинен потрапляти в git — додайте його в `.gitignore`
- Для реального проєкту (не портфоліо-демо) варто додати валідацію email на бекенді та rate-limiting на /login, щоб захиститись від підбору паролів
